# 数据源说明（必读）

## 为什么不是「爬虫」

本项目要求：**不使用 API / API Key / 付费数据接口，不伪造播放量、点赞量、热度与排名。**

在此约束下，抖音与快手都**没有**面向个人开发者的公开免鉴权数据接口。任何「自动抓取」都需要：

- 逆向平台签名算法（`a_bogus` / `X-Bogus` 等），属于绕过技术保护措施；
- 或复用登录态 Cookie，涉及账号与个人信息；
- 两者都违反平台用户协议，且随时失效。

因此 V1.0 采用的方案是：**人工核验快照 → 脚本校验清洗 → 静态 JSON 入库**。

这仍然满足「每天 08:00 自动更新」的技术要求：定时任务会准时执行、校验、入库、提交、部署，并在页面与日志中留下记录。**变化的是数据来源，不是自动化链路。**

## 怎么填

1. 复制 `curated.example.json` 为 `curated.json`（脚本只读这个文件名）。
2. 按字段填写你**亲自在平台公开页面看到**的信息。
3. 提交到仓库，或本地执行 `npm run update:data`。

```bash
cp scripts/sources/curated.example.json scripts/sources/curated.json
npm run update:data:dry   # 先预演，只校验不写盘
npm run update:data       # 正式写入 public/data/*.json
```

## 铁律

| 规则 | 说明 |
|---|---|
| 指标只能是**非负整数或 null** | 脚本会拒绝 `"1.2万"`、`"约5万"`、`"100+"` 这类写法 |
| 不知道就填 `null` | 页面显示「未公开」，绝不显示 0 |
| `rank` 必须来自平台公开榜单 | 没有名次就不要填，页面会隐藏排名列 |
| `url` 必须是 `https` + 官方域名 | 只允许 `*.douyin.com` 与 `*.kuaishou.com` |
| 每条必须写 `source` 与 `collectedAt` | 用于追溯口径与时间 |
| `id` 全局唯一 | 重复会让整次更新失败 |

## 失败会怎样

任何一条校验不通过 → **整次更新放弃，不写入任何文件**，上一次的有效数据完整保留，同时向 `public/data/logs.json` 写入一条 `failed` 日志，GitHub Actions 该次运行标红。

## 想接入自动化数据源

如果你后续获得了平台**书面授权**或官方开放接口，只需在 `scripts/update.mjs` 里新增一个「拉取 → 转成同样的 snapshot 结构」的函数，后续校验与入库逻辑完全复用。校验层是唯一的数据入口，不要把数据直接写进 `public/data`。
